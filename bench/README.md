# Field benchmark

This folder lets anyone check what the kit does on real published figures, and re-run the numbers quoted in the README. It is not shipped in the npm package (`files` in `package.json` lists only `dist`, the README, `METHOD.md`, the license and the changelog).

```sh
npm run bench     # builds, regenerates the cases with the Python oracle, runs the kit, checks the headline numbers, then runs the holdout
```

`npm run bench` needs `python3` (standard library only) and Node 20 or newer. It exits 1 if a headline number in `expected.json` changes or if the kit disagrees with a holdout label.

## What is compared with what

Each case is a claim built from a count and a printed percentage that appear in a public document, and each has a verdict decided by `oracle.py` before the kit sees it. The oracle is a second implementation of the kit's documented rules: Wilson intervals in 60-digit decimal arithmetic, rate equality in exact fractions, written from the README's verdict table and sharing no code with `src/`.

That caveat matters. Agreement with the oracle shows the kit does what its README says. It does not show that the README's rules are the right ones, and the oracle shares its author with the kit. The holdout (`holdout/`) is the check that does not use the oracle: its verdicts were decided from the rules and from reading each source, and written down before the kit ran.

## The FDA corpus (`fda/`)

- Source: the "510(k) Summary" documents the US FDA posts for cleared devices, from 2021 to 2026, found through the openFDA listing. 75 documents, 216 printed rates with counts (for example "Sensitivity: 60.7% (116/191)"), 2 per document and rate type at most, picked with a fixed seed.
- `items.jsonl`: one row per rate. It holds the counts, the printed percentage, the printed confidence interval, the document number and the URL. It does not hold any source text, and no PDF is stored. To find a row in its PDF, search the text for the `find` field (`116/191`).
- `build.py` turns each rate into judged claims: the printed figure and nine altered versions of it (rounded up, plus three points, claimed as 100%, five points under, a floor taken from the published interval, the complement error rate, error ceilings), under three option sets; the same figures as claims about a whole fixed set; the printed figure with the document's own sampling and label source (read from its text by fixed rules, `declarations.json`); and 95 tables of site-level counts that also print a total (`strata.json`).
- `cases.jsonl` is generated by `build.py` and is not committed. `build.py --subset` writes the small slice the test suite runs on every commit (`test/fixtures/field-regression.json`, 547 cases).

## What `npm run bench` prints

Every number carries its denominator. The headline numbers it reproduces:

| What | Number |
| --- | --- |
| Printed rates, documents | 216 rates in 75 documents |
| Judged claims, default options | 2,001 (1,959 without the 42 written as printed percent divided by 100) |
| Claims the counts do not carry (oracle: overstated or contradicted) that the kit passed as `supported` | 0 of 957 |
| Claims the counts carry (oracle: supported) that the kit said `supported` | 726 of 726 |
| Kit verdict equals oracle verdict | 2,001 of 2,001 default; 2,001 of 2,001 `strictPrecision`; 2,001 of 2,001 `conservative` |
| Same, with the document's declared sampling and label source | 216 of 216 |
| Same, as claims about a whole fixed set (named, unnamed, held-out split) | 3,498 of 3,498 |
| Same, pooled site tables | 95 of 95 |

`expected.json` pins these. A change in the kit that moves one is a finding to explain, not a number to edit.

## What this does not show

- It covers one document family, FDA 510(k) summaries of diagnostic devices. The holdout adds claims from a different family.
- 29 of the 216 printed intervals matched no standard method (Wilson, Clopper-Pearson, Wald) to the printed digits; they were not audited. The kit never reads a printed interval, so this does not change a verdict.
- The sampling and label source for the "declared" suite come from keyword rules over each document's text, applied before the kit ran. They are declarations, not facts about how the studies were run.

## The holdout (`holdout/`)

103 public accuracy claims with printed counts from 30 open-access papers and a vendor benchmark page, none from the FDA corpus, labeled by hand before the kit was run: the kit agrees on 103 of 103 (73 supported, 24 refused, 4 contradicted, 2 overstated). `node bench/holdout/run.mjs` reproduces it; `holdout/README.md` says what it does not show.

## Heuristic rates (`heuristics.mjs`)

`node bench/heuristics.mjs` measures the kit's policy choices and prints each with its denominator: how many printed rates the default minimum sample size refuses, how many honest printed rates `strictPrecision` and `conservative` would stop supporting, how often the strata check refuses samples whose strata truly have one rate (a fixed-seed simulation), and how often the true rate is below a claim set at the lower end of the interval or equal to the observed rate (also simulated). `expected.json` pins them under `heuristics`; `METHOD.md` quotes them. Simulated numbers describe the simulated populations (listed in the script), not real studies.
