# Engineering contract

This package is pure TypeScript/ESM statistics on caller-supplied counts. It has no UI, storage, network, clock or randomness. The source entry is `src/index.ts`; the package export resolves to generated `dist/index.js`.

## Invariants and critical paths

- **Refusal is "cannot tell".** `assessAccuracyClaim` returns `refused` when a precondition fails (no human labels, ranked/convenience/unknown sampling, `n < minN`, merged strata that differ, known retractions not in the counts, a failed agreement gate, an agreement statistic computed on fewer than `minN` items). A refusal outranks any other verdict, lists every failed precondition, and returns no interval, so no number is there to quote.
- **Malformed input throws; it never produces a verdict.** `TypeError` for a wrong runtime type, `RangeError` for an unusable value. Nothing is coerced: strings are not numbers, `Number` objects are not numbers, `-0` is read as `0`.
- **Observed-rate allowance.** A point claim equal to the observed rate to its printed precision (`matchesObserved`) is `supported`; with no display the value stands in for the print and is read as the shortest decimal within the value-noise allowance of it (`valueDigits`, `VALUE_NOISE` in `src/exact.ts`), never coarser than a whole percent (`COARSEST_VALUE_SCALE`), and a value within the allowance of the printed figure is that figure (`beyondNoise`); bounds, 0 and 1 (and `options.conservative`) never use it. A value within the allowance of 0 or 1 is read as 0 or 1 (`snapAbsolute`), so a computed 100% (ten 0.1s added up) is an absolute claim. Display forms are parsed in `src/display.ts` into one judged figure; the parsed form is returned.
- **`1 in N` is exact.** N is read to plus or minus one half. Only a figure written as approximate (`about`, `around`, `roughly`, `approximately`, `~`, `≈`) treats the trailing zeros of N as placeholders (`about 1 in 100` covers 1 in 50 to 1 in 150). A bound on it (`fewer than 1 in 1,000`) is a bound at 1/N; a bound written after it (`1 in 100 or lower`) is ambiguous and throws. The band that was applied is named in the explanation (`bandNote` in `src/display.ts`).
- **Excess printed precision is informational** unless `options.strictPrecision` or `options.conservative` is set; a contradicted claim stays contradicted.
- **Every visible figure is judged by its form on every path.** A range is judged at its favorable end as a point; strict bounds exclude equality; a value more favorable than the printed figure is judged as its own point. The observed-rate exception runs before `contradicted`.
- **Undisclosed n is a refusal.** `sample` may be omitted; malformed or half-given counts throw.
- **Complete sets are exact.** With `sampling: 'complete'` there is no interval: the figure is compared with `k / n` by integer arithmetic (`src/census.ts`), a mismatch is `contradicted`, and the claim text must name the benchmark. Stratified sampling without strata is refused, never pooled silently.
- **Age and scope are declared, not read.** `evaluatedAt`, `options.now` and `options.maxAgeDays` are `YYYY-MM-DD` strings checked as real dates (`src/dates.ts`); the kit never reads a clock. Populations are identifiers compared after NFKC, lower-casing, whitespace folding, typographic quotes and dashes folded to ASCII, and every invisible default-ignorable character (the soft hyphen, zero-width space, joiners, direction marks, BOM, variation and tag characters) dropped (`src/text.ts`). Names and populations need a letter or digit. `mentionsName` looks only at the code points next to a match (surrogate-aware), so it is linear in the text; a `+` or a joiner then a letter or digit is not a clean boundary. Labels and stratum names are capped at `MAX_LABEL_LENGTH` = 1000 characters, because equal-length strings over 16,383 characters collide in V8 Map and Set hashing.
- **Metric names speak the claimant's words.** `specificity`, `npv` and the diagnostic aliases (`sensitivity`, `ppa`, `ppv`, `npa`, `opa`) are higher-is-better proportions judged like `recall`, `precision` and `accuracy`; only the statement's wording differs (`METRIC_PHRASE` in `src/assess.ts`). A negatives-only figure must not be called "accurate".
- **Statements lead with their scope.** An interval statement starts `On this sample` (or `On this sample of <population.evaluated>`), so a pasted headline cannot read as a property of the system, and says the interval covers sampling error only (a cross-validation estimate also says it is optimistic). A complete-set statement says it describes that set only.
- **`claim-worse-than-counts` is informational.** It is appended when a figure is outside the 99.9% interval on the pessimistic side and never changes the verdict.
- **`strata-not-reweighted` is informational.** Every non-refused result with `sampling: 'stratified'` carries it, and its statement says `stratified sample, unweighted pooled`. The interval pools the strata; the kit has no population shares and does not reweight.
- **`text-figure-differs` is informational.** `claim.text` is scanned (`textFiguresDiffering` in `src/display.ts`, at most 50 figures, linear in the text) with the same parser as `display`; a figure that describes neither `value` nor the judged display nor their complement adds the code to a non-refused result. It never changes the verdict and refusals do not carry it.
- **Echoed strings are plain.** `benchmark.name`, `population.claimed`, `population.evaluated` and stratum names reach explanations and statements, and `claim.text` is scanned for the figures a reader will see (it is never quoted whole: only the figures read from it are), so the kit must read the same text the reader does. `assertPlainText` (`src/text.ts`) rejects C0 and C1 controls (the tab is allowed), U+2028, U+2029, U+202A to U+202E and U+2066 to U+2069 with a `RangeError` that names the field and the code point and never echoes the string. A tag character or variation selector (which can carry hidden text) in a name, population identifier or stratum name throws the same way, and the other invisible characters (zero-width space, word joiner, BOM, the fillers, the braille blank) are dropped before the string is echoed (`shownText`); joiners, direction marks, the Arabic letter mark, the soft hyphen, the grapheme joiner and the emoji selectors stay. Error messages quote a caller string only through `clip`, which writes controls, separators, bidirectional and invisible characters as `\uXXXX`, so a message is always one clean line. A parsed `display` is echoed only in its folded form.
- **Options are a plain object.** `assertPlainObject` (`src/validate.ts`) rejects a built-in (`Map`, boxed primitive, `Date`, `Set`) as the `options` of `assessAccuracyClaim`, `wilsonInterval` and `gwetAC1`, because an object with no own keys would read as "no gates asked for" (or the default confidence or category count). A `sample` with none of `n`, `correct`, `errors` is an undisclosed sample (a refusal) whatever its type, which is the safe direction; a misspelled key throws.
- **Lengths are validated.** Every captured array `length` goes through `readLength` (whole number, 0 to `MAX_ITEMS` = 10,000,000) before a loop uses it; a Proxy cannot make the kit spin or return `NaN` counts.
- **The printed figure is judged.** With a `display`, the more favorable of `value` and the parsed display is compared with the interval (`assessedValue`); a display that disagrees with `value` by more than half a unit of its last digit plus one ulp of the value throws, judged exactly on the double's value (`src/exact.ts`), with no float tolerance. Decimal digits are range-checked (0 to 100) before conversion. `assessedValue` is set before refusals.
- **Inputs are read once.** Each caller property is read exactly once into a local before any judgment; no `toJSON`, no `then`. Arrays are walked by index with `length` read once. The own enumerable keys of each plain caller object (input, claim, sample, provenance, agreement, strata entries, retractions, benchmark, population, and the options of `assessAccuracyClaim`, `wilsonInterval` and `gwetAC1`) are listed exactly once, without reading a value, and an unknown key throws a `TypeError` that names it and the nearest valid key (`assertKnownKeys` in `src/validate.ts`); inherited and symbol keys are not looked at. A misspelled optional key must never turn a check off silently. The result's `checks` (`retractions`, `scope`, `age`, `agreement`, `strata`: `applied` or `not-supplied`) shows which optional checks ran.
- **Tolerance.** `COMPARISON_TOLERANCE` (1e-12, absolute, in proportions) is the only floating-point slack when a claim is compared with an interval limit. The one other allowance is `VALUE_NOISE` (2^-50, about 8.9e-16, absolute), which says how far a value may sit from the decimal or the rate it was computed as (`1 - correct / n` is a few ulps of 1 away from `errors / n`, which is hundreds of ulps of a small result); it needs about 1e15 items to matter and a value within it of 0 or 1 is read as 0 or 1. It always favors the claimant: a claim within the tolerance of a limit is treated as being at it. Accuracy exactly at the lower limit is `supported`; exactly at the upper limit is `overstated`; error rate mirrors this. Do not widen it without re-deriving its reach: it exceeds the interval width only above about 4e12 items with a rate within about 1e-12 of 0 or 1 (the width of an all-correct sample is about 3.84 / n: 1e-12 at n = 3.84e12, 4e-16 at `n = 2^53 - 1`). A claim of exactly 0 or 1 is absolute and never uses it (`tolFor` in `src/assess.ts`), so a 0% error claim on zero errors is `overstated` at every size.
- **Wilson interval.** Lower limit `s^2 / (n (A + B))` (no cancellation); upper limit `(A + B) / (n + z^2)` up to the midpoint and `1 - lower(n - s)` after it, so `s = 0` gives `low` exactly 0, `s = n` gives `high` exactly 1, and limits near 0 keep relative accuracy. `low <= point <= high` is enforced after computing.
- **Agreement statistics** use `BigInt` integer arithmetic and return a distinct `undefined` result (never `NaN`) when the formula has no value.
- **Bounds round cautiously** in statements and explanations: lower limits down, upper limits up, exactly (BigInt on the double's mantissa and exponent, no slack). Confidence labels are rounded down from the shortest decimal text and never print 100%.
- **No clock, no randomness** in `src/`. Test data that looks random comes from the seeded Python generator.

## Setup and verification

Declared dependencies are TypeScript, ESLint, Vitest and packaging tools in `package-lock.json`. For a clean environment use `npm ci`.

```sh
npm run verify
npm run attw
npm run audit:dependencies
```

`attw` checks the packed package's type resolution (the `cjs-resolves-to-esm` rule is ignored on purpose: the package is ESM only). `audit:dependencies` audits dev tooling only; there are no runtime dependencies.

The verdict table (`test/verdict-table.test.ts`) is the regression record: honest inputs that must pass and bad inputs that must be flagged. Numeric vectors (`test/numerics.test.ts`) come from `test/fixtures/generate_vectors.py`, an independent standard-library implementation (60-digit decimal for Wilson, exact fractions for agreement, `NormalDist().inv_cdf` for z).

Two further checks do not depend on this package's own reasoning. `test/reference.test.ts` compares the kit with statsmodels, scipy, scikit-learn and irrCAC (numbers in `test/fixtures/reference.json`, written by `scripts/reference/gen.py`, a developer tool) to a maximum absolute difference of 1e-12. `test/field-corpus.test.ts` runs a slice of the published-rate benchmark in `bench/` against an oracle written from the README (`bench/oracle.py`); `npm run bench` runs the whole corpus and checks the headline numbers pinned in `bench/expected.json`. `bench/heuristics.mjs` measures the policy defaults (minimum n, precision rule, strata check, observed-rate allowance) over the same corpus and with a fixed-seed simulation, and pins the numbers `METHOD.md` quotes. `bench/` and `scripts/reference/` are not in `files`, so neither ships.

## Packaging

`scripts/verify-package.mjs` packs the build, installs the tarball into a clean project offline, imports every export, compares names with `api-surface.json`, runs `scripts/consumer-probe.mjs`, and type-checks `scripts/consumer-probe.mts` under strict NodeNext. It requires `LICENSE` in the tarball, `license: MIT` and no `private` flag in `package.json`, and fails if the tarball holds anything other than `dist/`, `README.md`, `METHOD.md`, `LICENSE`, `CHANGELOG.md` and `package.json`.

## Release and CI

The package is public (MIT). `.github/workflows/verify.yml` runs on every pull request and push to `main`: audit, lint, typecheck, test, build, `attw` and the installable-package check on Node 26.3.0, plus a compatibility matrix (Node 20, 20.19.0, 22, 22.12.0, 24) that builds, tests and packs. `engines.node` is `>=20`, which the matrix covers. Actions are pinned by commit SHA and checkout does not persist credentials.

`.github/workflows/release.yml` publishes. It runs only on a `v*` tag (a manual run must also start from a tag), checks that the tag equals the `package.json` version, runs the audit, `npm run verify` and `attw`, asks the registry whether that version already exists (only a confirmed `E404` means it does not; any other registry error fails the job), and then runs a plain `npm publish` with `id-token: write` under npm trusted publishing, which signs provenance without a stored token. Trusted publishing must be linked to this repository and workflow on npmjs.com before the first tag. A published `name@version` can never be reused, so fix forward with a new version. Nobody runs `npm publish` by hand; `prepublishOnly` runs `npm run verify` as a second guard.
